# 适配其他版本服务端

按“真实正常客户端 → 目标服务端处理 → 对应协议/脚本 → 假人行为”跟踪调用链。不同版本单独建立配置、测试账号和发布记录。

## 1. 认证与进场

实现 `local_auth.build_hello(account)` 和 `build_auth(account, challenge)`，返回完整 bytes 数据包。`challenge` 是服务端握手应答的完整帧，包含包头；账号密码通过本地私有配置或环境传入，不写进代码或日志。

当前扩展点只覆盖原协议下的两步登录。若目标版本需要多轮挑战、密钥交换或不同包头，应修改 `SimpleBot.login()` 和包编解码，不能只塞入一个固定认证包。认证成功需要解析真实结果码，现有消息编号分支不能作为其他版本成功凭证。

引擎当前使用 6 字节包头及固定消息字段。逐项确认长度编码、消息编号、会话状态、密码校验、角色列表、选角、场景初始化与心跳。认证模块缺失时在网络连接前报错。

## 2. 移动与地图

核对坐标单位、移动包、路径节点、停止反馈和进场确认。用目标版本数据生成路径文件与哈希 manifest；建立普通出口连接，不默认传送真人队员。先测同地图，再测多出口连续赶路。具体节点数量、地图格式见 `hunt_navigation.py`；不要用其他版本的障碍和出口直接替代。

## 3. 队伍与战斗

核对邀请/申请/批准、成员变更、队长身份和组队跟随通知。区分长期 GUID 与场景 ObjID，切图后重新获取对象身份。测试晚入队、战斗中加入、过图掉队和真人停留后的恢复。

队员默认只打队长有效目标；马贼队长才由任务自主找怪。核对技能、攻击距离、冷却、死亡/移除消息，不能把无应答当作攻击成功。

## 4. Lua 集成

`server/Jiaren.lua` 是版本相关参考，UTF-8 保存。安装前按目标服要求转码并检查 Lua 语法/API。原实现采用脚本编号 9998496、入口 `Jiaren`；检查编号冲突，在目标服脚本注册与允许调用清单中对应配置，**不要覆盖整份注册文件**。

公开副本对 Jiaren 入口增加受管 GUID 白名单检查。`bot_speaker_allowlist.txt` 路径需按目标安装位置修改，缺失时拒绝调用。测试管理员自行生成名单，不把真实 GUID 文件提交到仓库。

原有查询包括马贼位置/生命、队长位置和聊天上下文；补刷调用活动脚本接口。必须逐项确认 API、参数、结果、冷却和副作用。普通 NPC/道具脚本不随仓库发布；小喇叭需在自己的合法脚本中对接同等白名单检查，保留普通玩家原流程。

## 5. 数据库与装备

先完成纯协议上线和行为，再接数据库。现有 SQL、物品字段、数据库名和二进制版本哈希只属于原实现参考，不能自动认定适合目标版本。验证表结构、编码、物品唯一性、铭文、真正离线及缓存保存后，逐项实现被阻断入口。

开启 enable_database_writes 仅表达本地开发配置，不能代替备份、版本校验、离线检查与事务。没有验证前不在正式服打开。精确位置接口不要直接照搬其他版本的进程偏移。

## 验收清单

- 正确密码可进，错误密码拒绝；选角、进场、在线稳定。
- 同地图绕障碍、上下马、普通出口过图与模型显示正常。
- 两个假人组队，再加入真人；跟随、协攻、晚入队与掉队恢复正常。
- 马贼可找到、可交互、可击杀，死亡目标被清理，下一目标正常。
- 多队运行不串配置；异常断开、无怪、路径不可达有可解释反馈。
- 所有改库结果退出重登后保存；其他角色数据不变。

每项附版本哈希、操作步骤、脱敏日志和实际观察。离线检查不等于游戏内验收。
